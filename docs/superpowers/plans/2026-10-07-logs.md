# Readable dev logs and log content — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `LOG_FORMAT=pretty` gives a colored, one-line-per-event console in dev while production keeps
the masked JSON; a bank that is down logs one line naming the host and the real cause instead of
`failed: null` plus 40 lines of stack; every job and bank call logs which job, merchant and operation
it belongs to.

**Architecture:** Phase A (Tasks 1–2) lives in `gateway-app/observability` and `logback-spring.xml`:
three logback converters (masked message, masked throwable, MDC context), a filter that picks the
appender, and a `LoggingProperties` guard that fails startup on an unknown format. Phase B: Task 3 is
a transport-failure describer in `gateway-providers`; Task 4 collapses expected provider failures in
the throwable rendering shared by both formats; Task 5 adds a tiny MDC scope (`LogContext`) in
`gateway-payments` used by `JobRunner`, `ReconciliationService` and `ProviderGateway`.

**Tech Stack:** Java 25, Spring Boot 4.0.7, Logback 1.5, logstash-logback-encoder 8.1, SLF4J MDC,
JUnit 5, AssertJ, Mockito.

**Spec:** `docs/superpowers/specs/2026-10-07-logs-design.md`

## Global Constraints

- Branch `feat/logs`. English in code, comments, log text and commits; DECISOES in Portuguese.
- `LOG_FORMAT` accepts exactly `json` (default) and `pretty`; anything else fails startup naming
  `LOG_FORMAT`.
- Every byte written by either format goes through `Masker` — message and throwable.
- `correlationId` is never set by a job: `MerchantEvents` reads it for merchant webhooks and
  `CieloHttp`/`BoletoHttp` send it to the bank.
- New MDC keys: `job`, `jobId`, `merchant`, `env`, `provider`, `op`. Pretty shows `cid` (the
  `correlationId`), `job`, `merchant`, `env`, `provider`, `op` in that order; `jobId` only in JSON.
- Only `ProviderException` codes `UNAVAILABLE` and `TIMEOUT` are collapsed to one line.
- Merchant-facing error codes and messages do not change (`ProviderErrors` stays as is).
- ArchUnit unchanged: `payments` imports no `providers`; `LogContext` uses SLF4J only.
- Lines at 100 columns (repo `CLAUDE.md`): run `./mvnw spotless:apply` before each commit.
- Verify: `./mvnw -B spotless:check verify` (Docker running).

## Review Focus

1. **A secret in an exception message, pretty format.** `gk_live_…` inside a cause's message must be
   masked in the pretty stack exactly as in JSON. Test in Task 1 (`masksTheStackTrace`).
2. **A typo in `LOG_FORMAT`.** `LOG_FORMAT=prety` must still print (as JSON) and the startup must
   fail with a message naming `LOG_FORMAT`. Tests in Task 2 (`unknownFormatStillWritesJson`,
   `rejectsAnUnknownFormat`).
3. **A thread reused after a job threw.** MDC keys from a failed job must not leak into the next log
   on that thread. Test in Task 5 (`clearsTheContextEvenWhenTheHandlerThrows`).
4. **A `DomainException` wrapping an `UNAVAILABLE`.** `ProviderErrors.toDomain` wraps the bank failure;
   logging that wrapper must also collapse. Test in Task 4 (`collapsesWhenTheProviderFailureIsACause`).
5. **A URL with a query string in a transport failure.** The host goes in the message; the query
   (`?inicio=…`, tokens on other APIs) must not. Test in Task 3 (`neverIncludesPathOrQuery`).

`LogContextConverter.java`:

```java
package com.gateway.app.observability;

import ch.qos.logback.classic.pattern.ClassicConverter;
import ch.qos.logback.classic.spi.ILoggingEvent;
import java.util.LinkedHashMap;
import java.util.Map;
import java.util.StringJoiner;

/**
 * The pretty format's {@code %logContext}: the MDC keys a reader needs, in a fixed order, values
 * whole so an id can be pasted into a query. {@code jobId} stays out on purpose (JSON has it).
 */
public class LogContextConverter extends ClassicConverter {
  private static final Map<String, String> LABELS = new LinkedHashMap<>();

  static {
    LABELS.put("correlationId", "cid");
    LABELS.put("job", "job");
    LABELS.put("merchant", "merchant");
    LABELS.put("env", "env");
    LABELS.put("provider", "provider");
    LABELS.put("op", "op");
  }

  @Override
  public String convert(ILoggingEvent event) {
    Map<String, String> mdc = event.getMDCPropertyMap();
    StringJoiner context = new StringJoiner(" ", "[", "] ");
    context.setEmptyValue("");

    LABELS.forEach(
        (key, label) -> {
          String value = mdc.get(key);
          if (value != null && !value.isBlank()) {
            context.add(label + "=" + value);
          }
        });

    return context.toString();
  }
}
```

```java
package com.gateway.app.observability;

import org.springframework.boot.context.properties.ConfigurationProperties;

/**
 * Readiness guard for {@code LOG_FORMAT}. logback-spring.xml cannot fail on its own, so a typo would
 * quietly pick a format; failing here names the variable. The logback filter sends every value that
 * is not exactly "pretty" to JSON, which is what keeps this failure visible.
 */
@ConfigurationProperties(prefix = "gateway.logging")
public record LoggingProperties(String format) {

  public LoggingProperties {
    if (format == null || format.isBlank()) {
      format = "json";
    }
    if (!format.equals("json") && !format.equals("pretty")) {
      throw new IllegalStateException(
          "gateway.logging.format="
              + format
              + " is not a log format; set LOG_FORMAT to json (default) or pretty");
    }
  }
}
```

`LogFormatFilter.java`:

```java
package com.gateway.app.observability;

import ch.qos.logback.classic.spi.ILoggingEvent;
import ch.qos.logback.core.filter.Filter;
import ch.qos.logback.core.spi.FilterReply;

/**
 * Both console appenders stay attached; this decides which one writes. Anything but exactly
 * "pretty" goes to JSON: an appender-ref by name would leave logback with no appender on a typo, and
 * then the {@link LoggingProperties} failure that reports the typo would print nowhere.
 */
public class LogFormatFilter extends Filter<ILoggingEvent> {
  private String format = "json";
  private String accept = "json";

  public void setFormat(String format) {
    this.format = format;
  }

  public void setAccept(String accept) {
    this.accept = accept;
  }

  @Override
  public FilterReply decide(ILoggingEvent event) {
    boolean isPretty = "pretty".equals(format);
    boolean wantsPretty = "pretty".equals(accept);

    return isPretty == wantsPretty ? FilterReply.NEUTRAL : FilterReply.DENY;
  }
}
```

```java
package com.gateway.app.observability;

import ch.qos.logback.classic.spi.IThrowableProxy;
import ch.qos.logback.classic.spi.ThrowableProxy;
import com.gateway.kernel.provider.ProviderException;
import java.util.EnumSet;
import java.util.IdentityHashMap;
import java.util.Map;
import java.util.Optional;
import java.util.Set;
import java.util.StringJoiner;

/**
 * A bank that is down or slow is operations, not a bug: forty lines of HttpClient frames per
 * reconciliation pass buried the one line that mattered. Collapsed only for UNAVAILABLE and
 * TIMEOUT; UNAUTHENTICATED, INVALID and anything that is not a ProviderException keep the stack,
 * because someone has to read those. The chain's classes and messages stay, so the root cause is
 * still on the line (DECISOES 2026-10-07).
 */
final class ExpectedProviderFailure {
  private static final Set<ProviderException.Code> EXPECTED =
      EnumSet.of(ProviderException.Code.UNAVAILABLE, ProviderException.Code.TIMEOUT);

  private ExpectedProviderFailure() {}

  static Optional<String> oneLine(IThrowableProxy proxy) {
    if (!(proxy instanceof ThrowableProxy throwableProxy)) {
      return Optional.empty();
    }
    Throwable logged = throwableProxy.getThrowable();

    StringJoiner chain = new StringJoiner(" ← ");
    boolean expected = false;
    Map<Throwable, Boolean> seen = new IdentityHashMap<>();
    for (Throwable current = logged; current != null; current = current.getCause()) {
      if (seen.put(current, Boolean.TRUE) != null) {
        return Optional.empty();
      }
      if (current instanceof ProviderException provider && !expected) {
        if (!EXPECTED.contains(provider.code())) {
          return Optional.empty();
        }
        expected = true;
      }
      chain.add(describe(current));
    }

    return expected ? Optional.of(chain.toString()) : Optional.empty();
  }

  private static String describe(Throwable thrown) {
    String name = thrown.getClass().getSimpleName();
    if (thrown instanceof ProviderException provider) {
      name = name + " " + provider.code();
    }
    String message = thrown.getMessage();

    return message == null || message.isBlank() ? name : name + ": " + message;
  }
}
```

```java
package com.gateway.payments;

import java.util.LinkedHashMap;
import java.util.Map;
import org.slf4j.MDC;

/**
 * Log-only context for work that has no request: which job, merchant, bank call. Never used for
 * {@code correlationId} — that key leaves the process (merchant webhooks, the bank's correlation
 * header), and a job inventing one would change what goes out. Pool threads are reused, so
 * {@link #close()} restores what was there before, nested scopes included.
 */
public final class LogContext implements AutoCloseable {
  private final Map<String, String> previous = new LinkedHashMap<>();

  private LogContext() {}

  public static LogContext with(String key, String value) {
    return new LogContext().and(key, value);
  }

  public LogContext and(String key, String value) {
    if (!previous.containsKey(key)) {
      previous.put(key, MDC.get(key));
    }

    if (value == null) {
      MDC.remove(key);
    } else {
      MDC.put(key, value);
    }

    return this;
  }

  @Override
  public void close() {
    previous.forEach(
        (key, old) -> {
          if (old == null) {
            MDC.remove(key);
          } else {
            MDC.put(key, old);
          }
        });
  }
}
```
